# 调试流程 Skill

当用户报告 Bug 或异常行为时，按照以下流程系统性排查。

## 调试流程（五步法）

### 1. 复现问题
- 确认**触发条件**：什么输入/操作/环境导致问题？
- 确认**表现**：实际结果 vs 预期结果
- 确认**范围**：是每次都出现还是偶现？影响所有用户还是特定场景？
- 收集**错误信息**：截图、错误日志、堆栈跟踪

### 2. 隔离范围
用二分法缩小问题范围：
- **前端问题**：是渲染问题还是数据问题？哪个组件？检查 props、state、API 响应
- **后端问题**：哪个路由/服务/函数？是请求问题还是响应问题？
- **数据库问题**：用 `db_query` 检查数据是否如预期
- **构建问题**：检查编译输出、依赖版本

### 3. 定位根因
使用以下工具查找原因：
- **查看代码**：`read_lines` 读取相关文件的关键部分
- **检查日志**：`read_process_log` 查看运行中进程的输出
- **审查代码**：`code_review` 检查 Python 代码规范问题
- **测试 API**：`api_request` 验证接口是否按预期响应
- **对比变化**：`watch_files` 监视文件变更，`git_operation diff` 查看代码差异
- **检查环境**：`env_manage list` 确认环境变量配置

### 4. 修复
- 小改动用 `edit_file` 精确搜索替换
- 大改动用 `file_read` + `file_write`
- 改完后更新测试：`edit_file` 修改测试用例

### 5. 验证
- **运行测试**：`run_tests runner=auto`
- **手动验证**：启动项目（`start_process`）并用 `api_request` 测试关键接口
- **确认无回归**：检查修改是否影响其他功能
- 验证通过后 `git_operation add + commit`

## 原则
- 一次只改一个问题
- 改完一个立即验证，不要批量修改后一起验证
- 如果 3 次尝试仍未找到原因，向用户汇报当前排查进展并请求指导
- 不要假设，用数据说话——用工具验证每个假设
