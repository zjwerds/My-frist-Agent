# 功能可行性分析报告

> 2026-07-06 | 基于现有代码架构评估三个新功能

---

## 功能一：Agent 回答框嵌入代码编译器

### 需求

Agent 输出代码时，代码出现在一个嵌在回答框中的编译器/编辑器里，右上角有复制按钮。

### 当前实现分析

目前消息渲染在 `MessageBubble.tsx` （`frontend/src/components/RightPanel/MessageBubble.tsx`）中通过 `MarkdownContent` 组件完成。代码块（```` ``` ````）被正则替换为 `<pre><code>` 标签。整个过程是纯文本到 HTML 的字符串替换：

```tsx
h = h.replace(/```(\w*)\n([\s\S]*?)```/g, '<pre><code>$2</code></pre>')
```

### 可行方案

#### 方案 A：替换 Markdown 渲染器为完整 Markdown 库（推荐）

| 步骤 | 内容 | 工作量 |
|---|---|---|
| 1 | 安装 `react-markdown` + `react-syntax-highlighter` | 5 min |
| 2 | 替换 `MarkdownContent` 组件，用 `react-markdown` 代替正则解析 | 1 h |
| 3 | 为 `react-syntax-highlighter` 配置代码块渲染，添加行号、复制按钮 | 1 h |
| 4 | 主题适配（浅色/深色主题切换） | 0.5 h |

**优势**：
- react-syntax-highlighter 原生支持 200+ 语言高亮、行号、自定义工具栏
- 复制按钮只需一行配置：`<CopyButton onClick={() => navigator.clipboard.writeText(code)} />`
- 社区维护，Edge cases 少（嵌套代码块、语言标记等）

**风险**：
- react-syntax-highlighter 包体积 ~150KB gzip，可能影响加载速度
- 需要验证是否支持 streaming（流式输出中代码块渐显）

#### 方案 B：用 Monaco Editor（VS Code 内核）

| 步骤 | 内容 | 工作量 |
|---|---|---|
| 1 | 安装 `@monaco-editor/react` | 10 min |
| 2 | 检测消息中的代码块，在最后一条 assistant 消息中嵌入 Monaco 编辑器 | 2 h |
| 3 | 配置只读模式、语言自动检测、复制按钮 | 1 h |
| 4 | 流式输出兼容处理（编辑器内容随 streaming 更新） | 2 h |

**优势**：
- 完整 IDE 体验：语法高亮、自动补全、错误提示
- 可直接编辑 → 满足了"嵌入编译器"的想象

**风险**：
- @monaco-editor/react 包体积 ~3MB，大幅增加前端打包体积
- 流式输出时频繁更新编辑器内容可能卡顿
- 与现有 dark theme 集成需要额外工作
- **不推荐用于仅展示代码的场景**，大材小用

#### 方案 C：CodeMirror（平衡方案）

| 步骤 | 内容 | 工作量 |
|---|---|---|
| 1 | 安装 `@codemirror/view` + `@codemirror/lang-python` 等 | 15 min |
| 2 | 检测代码块并嵌入 CodeMirror 只读编辑器 | 2 h |
| 3 | 复制按钮 + 语言标签 | 0.5 h |

**优势**：
- 介于方案 A 和 B 之间，包体积 ~200KB
- 真正的编辑器内核，支持语法高亮
- 性能优于 Monaco

**风险**：
- streaming 适配需要额外开发
- CodeMirror 6 API 较新，中文资料少

### 复制按钮实现（三个方案通用）

```tsx
function CopyButton({ code }: { code: string }) {
  const [copied, setCopied] = useState(false)
  return (
    <button onClick={() => {
      navigator.clipboard.writeText(code)
      setCopied(true)
      setTimeout(() => setCopied(false), 2000)
    }}>
      {copied ? '已复制' : '复制'}
    </button>
  )
}
```

### 综合推荐：方案 A → 方案 C（分阶段）

**第一阶段**（1-2 天）：替换为 react-markdown + react-syntax-highlighter，快速获得语法高亮和复制按钮。

**第二阶段**（未来）：如用户确实需要"在回答框里编辑代码后运行"，升级为 CodeMirror。

## 功能二：直接在左侧资源栏创建 .py 文件

### 需求

Agent 输出代码时，自动或手动创建一个 .py 文件出现在左侧项目资源管理器中。

### 当前实现分析

左侧 `ProjectExplorer.tsx` 已完整支持：

- ✅ 显示文件树（`filesApi.listDir`）
- ✅ 新建文件（`filesApi.createFile`）
- ✅ 新建文件夹（`filesApi.createDir`）
- ✅ 删除文件/文件夹（`filesApi.deleteFile`）
- ✅ 文件图标按扩展名自动匹配（.py 使用 Python logo SVG）
- ✅ 已对接 backend 文件系统 API

右侧 `FileViewer.tsx` 已支持查看文件内容。

### 实现方案

#### 在 ChatView 中加一个"创建文件"按钮

Agent 输出代码块时，在代码块右上角增加按钮：

```tsx
function CodeBlockActions({ code, language, currentProjectPath }) {
  return (
    <div className="flex gap-1">
      <button onClick={/* navigator.clipboard.writeText(code) */}>
        复制
      </button>
      {language === 'python' && currentProjectPath && (
        <button onClick={async () => {
          const name = prompt('文件名:', 'script.py')
          if (name) await filesApi.createFile(name, code, currentProjectPath)
        }}>
          保存为文件
        </button>
      )}
    </div>
  )
}
```

#### 各文件修改清单

| 文件 | 修改内容 | 预估 |
|---|---|---|
| `ProjectExplorer.tsx` | **无需修改**（已有完整的创建/显示功能） | — |
| `MessageBubble.tsx` | 在代码块区域添加"保存为文件"按钮 | 0.5 h |
| `ChatView.tsx` | 传入 `currentProjectPath` props（从 App.tsx 传递） | 0.2 h |
| API 层 | **无需修改**（已有 `filesApi.createFile`） | — |

### 工作量

**总计约 1 小时**，是三个功能中最简单的。因为底层文件操作 API 已全部就绪。

### 风险

- 需要确保文件编码为 UTF-8（后端已支持）
- 文件重名冲突：建议自动编号（`script_1.py`, `script_2.py`）

## 功能三：启动时提醒用户配置 Skill

### 需求

软件启动时，如果用户未配置 skill（或 skill 全部禁用），弹出提醒引导用户前往 skill 管理栏。

### 当前实现分析

启动流程（`App.tsx`）：
1. 显示全屏 loading 动画（等待后端启动）
2. 后端就绪后显示主界面
3. MenuBar 中有 SkillsPopover 入口

Skills 数据通过 API 获取，但启动时当前没有检查 skill 状态的逻辑。

### 实现方案

#### 第一步：后端新增接口（或复用现有）

查看技能列表 API。需要确认现有 API 是否返回 skill 启用状态。

#### 第二步：启动后检查

在 `App.tsx` 后端就绪后的 `useEffect` 中：

```tsx
const [showSkillReminder, setShowSkillReminder] = useState(false)

// 后端就绪后检查 skill 状态
useEffect(() => {
  if (!backendOk || backendStarting) return
  // 获取 skill 列表，检查是否有启用状态的 skill
  fetch('/api/skills').then(res => res.json()).then(skills => {
    const hasEnabled = skills.some(s => s.enabled)
    if (!hasEnabled) setShowSkillReminder(true)
  }).catch(() => {})
}, [backendOk, backendStarting])
```

#### 第三步：提醒弹窗

在 App.tsx 主界面之上叠加一个非阻塞提醒：

```tsx
{showSkillReminder && (
  <div className="fixed top-0 left-0 right-0 z-50 flex items-center gap-3 px-4 py-2.5 bg-[#2a2a4a] border-b border-[#3a3a5a] text-sm">
    <span className="text-gray-300">
      💡 在开始对话前，可以前往 <strong>工具 → 技能管理</strong> 选择你需要的技能
    </span>
    <button onClick={() => setShowSkillReminder(false)} className="ml-auto text-gray-500 hover:text-white">
      不再提示
    </button>
    {/* 或：记住选择 */}
    <button onClick={() => {
      localStorage.setItem('skill-reminder-dismissed', 'true')
      setShowSkillReminder(false)
    }} className="text-gray-500 hover:text-white text-xs">
      不再显示
    </button>
  </div>
)}
```

### 改进方向（可选）

- **一次性提醒**：首次启动时弹窗，之后不再显示（用 localStorage 记录状态）
- **Skill 推荐**：根据项目类型推荐启用哪些 skill（如 Python 项目推荐项目脚手架 skill）
- **内嵌引导**：提醒中直接提供"前往配置"按钮，点击自动打开 SkillsPopover

### 各文件修改清单

| 文件 | 修改内容 | 预估 |
|---|---|---|
| `App.tsx` | 添加 skill 检查逻辑 + 提醒弹窗 | 1 h |
| Skills API | 可能需要确认是否暴露了 enabled 状态 | 0.3 h |

### 工作量

**总计约 1.5 小时**，纯前端改动，无后端影响。

## 综合评估

### 优先级建议

| 功能 | 复杂度 | 用户价值 | 优先级 | 预估工时 |
|---|---|---|---|---|
| **② 保存为文件** | ⭐ 低 | ⭐⭐⭐⭐ 高 | **P0** | ~1 h |
| **③ 启动提醒** | ⭐ 低 | ⭐⭐⭐ 中 | **P1** | ~1.5 h |
| **① 代码编译器** | ⭐⭐⭐ 中 | ⭐⭐⭐⭐⭐ 高 | **P1** | ~2-3 天（分阶段） |

### 理由

1. **保存为文件**（功能二）现有基础设施最完善，几乎不需要修改后端和现有组件即可上线
2. **启动 Skill 提醒**（功能三）对新手用户体验改善明显，实施简单
3. **嵌入编译器**（功能一）价值最高但实施最复杂，建议分阶段推进。第一阶段用 react-markdown + react-syntax-highlighter 快速落地，第二阶段评估是否有必要升级到 CodeMirror

### 关键技术限制

1. **Streaming 兼容性**：三个功能都需要考虑流式输出的场景。代码块在 streaming 过程中是逐步出现的，需要确保嵌入组件在内容未完成时不出错。
2. **Electron 文件系统**：如果未来脱离 Electron（如纯 Web 版），"保存为文件"在浏览器沙箱中只能触发下载，无法自动保存到左侧资源栏。
3. **Skill API 状态**：需要确认后端 `/api/skills` 接口是否返回了 `enabled` 字段。如没有，需加 0.5 天开发。

### 建议实施顺序

```
Day 1:  功能二（保存为文件）+ 功能三（启动提醒）
Day 2-3: 功能一第一阶段（react-markdown + react-syntax-highlighter）
Day 4+:  功能一第二阶段（按需升级 CodeMirror）
```
