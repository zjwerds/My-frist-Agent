## 第二层：逐个分析

### 问题 1：Agent 不能在资源管理器创建/删除文件

**当前工具清单**（`backend/.tools/` 共 31 个工具）：

```
api_request, ask_user, code_review, db_query, edit_file, enter_plan,
env_manage, file_read, file_search, file_write, git_operation,
json_formatter, npm_install, ocr_image, pip_install, read_lines,
read_process_log, regex_tester, run_migration, run_tests, schedule_task,
search_memory, shell_command, spawn_subagent, start_process, stop_process,
task_track, translator, watch_files, web_fetch, web_search
```

**缺失的工具**：

| 缺少的工具 | 用户场景 | 当前行为 |
|-----------|---------|---------|
| `file_delete` | "删掉刚才的文档" | 模型只能口头确认，无法执行 |
| `file_rename` | "把 hello.md 改名为 readme.md" | 模型无法操作 |
| `dir_create` | "创建一个 src/utils 文件夹" | 已隐含在 `file_write` 中（自动创建父目录），但无单独创建目录的工具 |
| `dir_list` | 查看目录内容 | 仅后端 API 可用，Agent 无法主动调用 |

**根因**：不是模型能力不足，是**工具覆盖不完整**。模型在 ReAct 循环中只能调用已定义的工具。当用户要求删除文件时，模型找不到匹配工具，只能口头回复。

### 问题 2：模型"笨笨的"

**用户对话**：
```
用户：删除刚才的文档吧
模型：你是指刚才创建的 hello.md 对吗？内容只有「你好」那个。确认删除的话，我直接帮你删掉👇
用户：嗯
模型：有什么需要帮忙的吗？😊
```

**第一性原则分析**：

1. 第一轮：用户说"删除文档" → 模型意图识别正确 → 但找不到 `file_delete` 工具 → **只能口头确认，无法执行**
2. 第二轮：用户确认"嗯" → 模型知道用户确认了 → 但仍然没有 `file_delete` 工具 → **无法执行操作** → 退化为普通闲聊响应

**ReAct 循环的真实路径**：

```
用户请求 → LLM 决定调用工具 → 查找工具定义 → 无匹配工具 → 无法生成 tool_call
        → 模型只能生成文本回复 → 回复中承诺执行但实际上什么都没发生
```

这不是"模型笨"，是**工具链不完整**导致的 ReAct 循环断裂。

**解决方案**：补充 `file_delete`、`file_rename` 工具定义和实现。

### 问题 5：用户行为分析和记忆封装

```python
asyncio.ensure_future(
    _analyze_and_record(user_msg=..., ai_msg=..., api_key=..., base_url=..., model=...)

```

每轮回答后异步调用 `analyze_turn()`，结果写入 `analysis/user_behavior.md`。

**前置分析**（`chat.py:121-133`）：

```python

    user_msg=request.message,

    base_url=cfg.get("base_url", ...),

```

**记忆封装**（`chat.py:245-253`）：

```python
asyncio.ensure_future(
    _condense_and_save(conversation_id=..., user_msg=..., ai_msg=..., ...)
)
```

每轮回答后异步调用 `condense_turn()`，结果写入 `backend/memories/` 目录。

**当前状态**：两个功能**均已实现且正常运行**。但它们都是**异步、非阻塞**的 —— 不影响主对话流程，即使分析失败也不会报错给用户。

**关键约束**：这两个功能依赖模型 API 的额外调用（`AsyncOpenAI` 独立请求）。如果：
- API Key 失效 → 分析/封装静默失败
- 模型 API 超时 → 使用兜底记录（见 `_analyze_and_record` 的 `except` 分支）
- API 配额不足 → 分析/封装不执行

## 第四层：具体修复方案

### P0：增加文件操作工具

**第一步**：添加 `file_delete` 工具

在 `file_tools.py` 中添加：

```python
async def _file_delete(args: dict) -> dict:
    filepath = args.get("path", "")
    if not filepath:
        return {"error": "缺少文件路径"}
    path = Path(filepath)
    if not path.exists():
        return {"error": f"文件不存在: {filepath}"}
    if not in_workspace(path):
        return {"error": f"无权删除（超出工作区范围）: {filepath}"}
    try:
        path.unlink()
        return {"path": str(path.resolve()), "status": "deleted"}
    except Exception as e:
        return {"error": str(e)}
```

在 `tools/__init__.py` 中注册：

```python

# tool_map["file_delete"] = _file_delete
```
