# 文件上传与多模态理解方案

## 概述

在基于大模型的应用中，用户上传的文件（图片、文档）需要经过**格式适配 → 内容提取 → 模型理解**这三个阶段。本方案按"模型能力分级"设计，兼容 vision 模型和纯文本模型，并对齐行业主流实践（Claude、GPT-4o、Gemini）。

---

## 一、核心原则

### 1.1 模型能力分级

```
Level 1 — 纯文本模型（DeepSeek, GPT-3.5, 开源模型）
  → 所有文件均提取为文本后发送

Level 2 — 多模态模型（Claude 3.5+, GPT-4o, Gemini 2.0+）
  → 图片以 image_url / base64 直接发送
  → 文档提取文本后发送
```

### 1.2 输入格式标准

| 文件类型 | 模型接收格式 | 处理方式 |
|---------|-------------|---------|
| JPEG / PNG / WebP | base64 data URI 或 image_url | 直接发送（多模态）或 OCR（纯文本） |
| PDF | 纯文本 | 提取全部文本内容 |
| DOCX | 纯文本 | 提取段落文本 |
| XLSX | 纯文本 | 提取单元格文本（按 sheet 组织） |
| TXT / MD / CSV | 纯文本 | 直接读取 |
| DOC / XLS（旧格式） | 纯文本 | 同 DOCX/XLSX（需额外库支持） |

## 二、图片处理方案

### 2.1 多模态模型路径

```python
# 模型声明是否支持 vision
VISION_MODEL_PATTERNS = (
    "gpt-4o", "gpt-4-vision",
    "claude-3-opus", "claude-3-sonnet", "claude-3-haiku",
    "claude-4", "claude-sonnet-4", "claude-opus-4",
    "gemini-1.5", "gemini-2",
)

def supports_vision(model: str) -> bool:
    m = model.lower()
    return any(p in m for p in VISION_MODEL_PATTERNS)
```

构造多模态消息体：

```python
content = [
    {"type": "text", "text": user_message},
    {"type": "image_url", "image_url": {"url": image_data_uri}},
]
```

**格式要求**：
- 使用标准 Data URI 格式：`data:image/{format};base64,{base64_data}`
- 单张图片不超过 20MB（base64 编码后约 27MB）
- 每次最多 5 张图片（Claude 最多 20 张，GPT-4o 最多 10 张）

### 2.2 纯文本模型路径（OCR 兜底）

```python
def ocr_image(image_data_uri: str) -> str:
    """返回提取的文本，失败返回空字符串。"""
    from PIL import Image
    import pytesseract
    import io, base64, re

    try:
        raw = re.sub(r"^data:image/\w+;base64,", "", image_data_uri)
        img = Image.open(io.BytesIO(base64.b64decode(raw)))
        return pytesseract.image_to_string(img, lang="chi_sim+eng").strip()
    except Exception:
        return ""
```

**组装后的用户消息**：
```
{用户原始问题}

[图片中的文字]
{OCR 提取的文本}
---
{图片2的文字}
```

### 2.3 行业主流对齐

| 平台 | 图片处理方式 | 特点 |
|------|------------|------|
| **Claude**（Anthropic） | 原生多模态，支持 base64 和 URL | 自动理解图片中的文字、图表、代码 |
| **GPT-4o**（OpenAI） | 原生多模态，支持 base64 和 URL | 同 Claude |
| **Gemini**（Google） | 原生多模态，支持 base64 和 inline data | 文件大小限制较宽松 |
| **DeepSeek-V4** | 纯文本，不支持 image_url | 必须使用 OCR 提取文字 |
| **主流 Agent 框架**（LangChain, CrewAI） | 统一转文本后发送 | 对所有模型一视同仁 |
| **Cursor / Windsurf** | 截图 → base64 → 多模态模型 | 编辑器内截图直接发送 |

**结论**：行业标准做法是 —— 多模态模型直接发图片，纯文本模型走 OCR，无一例外。

## 三、文档处理方案

### 3.1 文件解析流程

```
用户选择文件
  → 前端读取文件（不显示二进制错误）
  → POST /api/upload/parse-file（流式上传，64KB 分块）
  → 后端检测扩展名
    → PDF → PyMuPDF 提取逐页文本
    → DOCX → python-docx 提取段落
    → XLSX → openpyxl 提取单元格（按 Sheet 分组）
    → TXT/MD/CSV → 直接读 UTF-8
    → 其他 → 返回"不支持的文件格式"
  → 返回 { text, pages, rows, size, warning? }
  → 前端将 text 拼入用户消息发送
```

### 3.2 文本组织格式

提取的文本按以下格式组织，便于 LLM 理解：

```
[PDF 项目报告.pdf]（共 5 页，3000 字）
────────────────────────────────
--- 第 1 页 ---
...
--- 第 2 页 ---
...

[Sheet: 数据总表]
A1 | B1 | C1
A2 | B2 | C2
```

### 3.3 大小限制与截断

| 维度 | 限制 | 策略 |
|------|------|------|
| 单文件大小 | PDF 50MB / DOCX 20MB / XLSX 20MB | 超过返回 HTTP 413 |
| 提取文本长度 | 100,000 字符 | 超过截断 + 提示语 |
| PDF 页数 | 500 页 | 超过返回错误 |
| XLSX 行数 | 10,000 行 | 超过截断 + 提示语 |

### 3.4 Agent 工具读取文件

Agent 在对话中通过 `file_read` 工具读取文件时，需要对文档格式做特殊处理：

```python
async def file_read(path: str) -> dict:
    path = Path(path)
    ext = path.suffix.lower()

    if ext in (".pdf", ".docx", ".doc", ".xlsx", ".xls"):
        # 文档格式：用文件解析器提取文本
        raw = path.read_bytes()
        result = parse_doc(raw, path.name)
        return {"content": result["text"], "format": ext[1:], ...}
    else:
        # 纯文本：直接读 UTF-8
        content = path.read_text("utf-8", errors="replace")
        return {"content": content}
```

**注意**：此方案仅适用于 Agent 能正确获取文件路径的场景。若用户通过前端界面"点击文件"而非"对话中告诉 Agent 路径"，则需要前端将文件内容塞入对话上下文。

## 四、前端集成方案

### 4.1 文件上传入口

两种方式：

| 方式 | 实现 | 适用场景 |
|------|------|---------|
| ChatInput 附件按钮 | `<input type="file">` + FormData 上传 | 用户主动上传文件给 Agent |
| ProjectExplorer 点击 | `fileApi.readFile()` → FileViewer 展示 | 浏览项目文件 |
| 拖拽上传 | `onDrop` → File → 自动上传 | 快捷操作 |

### 4.2 消息体结构

```typescript
// 发送到后端的消息
interface ChatRequest {
  message: string           // 包含：用户文本 + 文档解析文本
  images?: string[]         // base64 data URI 数组（多模态）或空（纯文本）
  conversation_id: string
}

// 文档走 message 字段，图片走 images 字段
// 二者互不干扰，可同时发送
```

### 4.3 用户侧流程

```
1. 用户拖入/选择文件
   ├── 图片 → 预览缩略图，存入 images[]
   └── 文档 → 显示附件 chip（状态: pending）

2. 用户输入问题，点击发送
   ├── 文档: 调用 /api/upload/parse-file 逐个解析
   │   └── 解析文本拼入 message
   ├── 图片: base64 data URI 存入 images[]
   └── POST /api/chat { message, images }

3. 后端处理
   ├── message 中的文档文本 → 模型直接理解
   ├── images 数组 → 多模态 or OCR
   └── 流式返回 SSE
```
